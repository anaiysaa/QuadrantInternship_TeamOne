4) Deep Dive — Each AI Feature

A. Employee Handbook AI Chat (RAG-like flow)

Primary files
backend/main.py (/api/ask), frontend/src/components/chat/AIChatWidget.jsx, backend/chunker.py, backend/azure_search_setup.py
Model/API
Azure OpenAI via openai.AzureOpenAI, chat completions API
Retrieval engine
Azure AI Search index queried via REST in search_employee_handbook()
  1. User asks a question in chat widget (AIChatWidget.jsx) and sends to POST /api/ask.
  2. Backend searches top handbook chunks from Azure Search (top_k=2).
  3. Backend constructs constrained prompt: “answer using only official handbook excerpts”.
  4. Azure OpenAI returns final response; backend returns {"answer": ...}.
  5. Frontend appends AI reply into chat conversation.

How knowledge base is built: chunker.py uses LangChain PyPDFLoader + RecursiveCharacterTextSplitter (chunk 500, overlap 50), writes JSON/CSV chunk files; azure_search_setup.py uploads chunks to Azure Search index.

B. Resume AI Pipeline (Upload → Parse → Normalize → Persist)

Primary files
backend/resume_ai/resume_api.py, backend/resume_ai/resume_nor.py, frontend/src/pages/Profile.jsx
Document extraction
Azure AI Document Intelligence (DocumentAnalysisClient, prebuilt-document)
Normalization model
Azure OpenAI (AZURE_OPENAI_DEPLOYMENT) returns strict JSON fields for employee profile + skills + certs
Storage
Upsert into dbo.Employees through pyodbc; skills/certifications stored as JSON strings
  1. Profile page uploads file to POST /resume/upload.
  2. process_resume_file() in resume_nor.py extracts full text via Document Intelligence.
  3. Prompt asks Azure OpenAI to produce clean JSON schema for resume entities.
  4. Code robustly extracts JSON (direct parse, then regex fallback block extraction).
  5. Employee record is updated or inserted by email key.
  6. API returns parsed result and lightweight regex sections for UI display.

C. Ticket Severity AI (IT + HR)

Primary files
backend/ticketAi/it_ticket_bot.py, backend/ticketAi/hr_ticket_bot.py, backend/main.py ticket routes
Model/API
Azure AI Inference SDK ChatCompletionsClient with SystemMessage/UserMessage
Prompt strategy
Severity rubric loaded from JSON (it_severity.json, hr_severity.json) with levels, examples, keywords, SLA expectations
  1. User submits ticket in Support Tickets UI.
  2. Backend POST /api/tickets/it or /api/tickets/hr calls classifier function with description text.
  3. Classifier builds large system prompt from severity schema and asks model for final severity line.
  4. Regex extracts Severity 1..5 from model output.
  5. Severity integer stored into SQL ticket row and shown in HR/IT queues and analytics charts.

Important detail: this is not embedding/ML training in-app; it is prompt-based LLM classification with domain rubric grounding from JSON configuration.

D. HR Ticket Summarization

Primary files
backend/ai_utils.py (summarize_ticket_description), backend/main.py (/summarize-hr-tickets)
Model/API
Azure OpenAI chat completions
  1. Endpoint loads HR ticket descriptions from SQL.
  2. For each ticket, utility prompts model to produce 1–2 sentence concise summary.
  3. Endpoint returns original + summary payload for quick HR triage.

E. Internal Transfer AI Recommendations

Primary files
backend/main.py (/apply-internal-transfer), backend/ai_utils.py
Model/API
Azure OpenAI with deterministic prompt (temperature=0.0)
  1. System gets employee skills and applied jobs from SQL.
  2. System derives missing skills per job and queries matching LMS courses from DB.
  3. LLM receives: current skills, required skills, available courses+links.
  4. LLM outputs structured recommendation list by missing skill.
  5. Endpoint returns both raw course candidates and AI-generated recommendation rationale.

F. Career Portal Matching (AI-adjacent, mostly deterministic)

Primary files
backend/resume_ai/job_match.py, backend/resume_ai/course_recommender_ai.py, frontend/src/pages/CareerPortal.jsx
Computation type
Rule-based skill overlap + SQL course lookup cache; no LLM in this specific flow
  1. Frontend requests /job/job-matches/:employeeId.
  2. Backend loads employee skills and all internal jobs.
  3. Computes intersection/missing sets and match percent.
  4. Maps missing skills to LMS courses using cached DB course list.
  5. Returns sorted match cards with recommended courses for UI rendering.

6) Implementation Notes for Handoff

  • Multiple implementations exist: there are both Flask and FastAPI-style chat/classifier modules in repo; the active integrated app path is Flask backend/main.py plus blueprints.
  • Prompt-centric design: classification and recommendation rely heavily on prompt instructions + schema/rubric text; behavior updates can be made without model retraining.
  • Structured output safety: resume parser includes JSON fallback extraction to survive imperfect model output.
  • Knowledge grounding: handbook chat attempts grounding by retrieving chunks first and forcing “use only excerpts”.
  • Data access layer: all AI outputs are persisted/combined with Azure SQL through pyodbc.

7) End-to-End User Journeys (Readable in Plain English)

Journey 1 — Employee asks handbook question

Employee opens dashboard chat, asks question, backend retrieves handbook chunks from Azure Search, LLM drafts answer constrained to retrieved text, UI displays final answer in chat stream.

Journey 2 — Employee uploads resume

Employee uploads PDF/DOC, Document Intelligence reads text, LLM normalizes into profile JSON, backend updates employee row, UI immediately reflects refreshed skills/education/certifications.

Journey 3 — Employee submits support ticket

Ticket description sent to backend, LLM classifier assigns severity 1–5 using IT/HR rubric, ticket saved with severity, support queues prioritize and display analytics by severity.

Journey 4 — Employee explores internal career opportunities

Backend compares employee skills with job mandatory skills, computes match %, identifies gaps, attaches recommended LMS courses, UI renders matched jobs and learning suggestions.
